# CLI 启动接入约定

此文件供开发者使用，不作为每个 attempt 的提示词重复注入。

1. 首次启动时提供本 skill、任务入口、用户目标、工作目录、工具连接及明确限制。题目与历史可由 CLI 按需读取，不复制旧 API 模式的大提示词。
2. 持续任务使用当前 CLI 会话，或按实际 CLI 能力恢复原会话。工具返回、结果通知属于后续对话，不是重新注入一份优化策略。
3. 不要同时强制加载 API 模式的 optimize-operator-round，不强制 CLI 保留每个历史版本全文，也不自行裁剪、摘要或重建 CLI 的内部会话。由 CLI 自主管理；平台仍持久保存源码、评测和交接资料。
4. skill 首次加载后作为会话指令生效；“只加载一次”不意味着删除指令。只有会话真正丢失、无法恢复且需要新建时，才重新提供启动指令与最新交接入口，不能依赖模型永久记忆。
5. 若 CLI 一次运行退出但任务仍 running，依据实际事件和交接记录恢复或继续；避免无进展的自动热循环。退出不等于任务完成，未知状态先查证。
6. 保留工具侧限频、暂停/停止、租约和迟到请求拒绝、结果对账。不能只靠 skill 实现人工停止。
7. 复用已有认证，不把密码/API key 放入启动文本。CLI 参数、MCP/工具支持、会话恢复方式须按真实安装版本核查，不能假定两种 CLI 行为一致。
8. 开发者验收：首次能自主读题和读取工作代码；连续两次修改无需新的人工策略提示；编译失败可沿失败版本修复；可自主结束一个方向并提出另一个；暂停和重启不会重复提交；换题无需改写通用 skill。

建议启动消息：

```text
使用 start-operator-optimization 开展持续算子优化。
任务 ID：<task_id>
工作目录：<workspace>
目标：<实际性能指标与正确性要求；详情从任务工具读取>
通过已配置的平台工具读取当前状态、题目与历史，自主推进。
不设累计资源预算，保留提交限频；直到用户暂停/停止或出现真实阻塞。
```

工具连接和任务状态由宿主真实提供，不能仅写在文本中。此 skill 不保证模型一定获得加速，需用实际评测检验优化质量。
