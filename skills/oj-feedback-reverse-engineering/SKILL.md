# OJ 反馈数据逆向

## 目的与工作方式

把评测反馈当成一条低带宽的信息通道：程序在运行时能看到输入元信息和元素，但不能直接打印；可以让输出中一个**可精确控制的数量**故意出错，从评测展示的错误率取回信息。

目标是获得用户所需的数据特征，用于构造相似测试、理解正确性边界或选择实现。题目可能是逐元素、归约、排序、矩阵或稀疏算子，**先决定要知道什么，再设计探针**。不要直接套用 CopySign 的五种类型、1D、N、固定常量或三轮方案。

默认使用中文解释。用户要求别的语言时跟随用户。本技能不要求特定平台、NPU、浏览器工具或第三方 Python 库。

用户提供题面、代码或反馈后，继续推进已授权的分析和代码修改。能从文件确定的信息先读取，不重复询问。没有提交工具时，准备好可直接提交的文件，给用户明确的提交动作并等待反馈；不要虚构已经运行过 OJ。

## 先读哪些附录

- **首次设计错误率探针，或算数出现歧义**：读 [反馈数学与精度](references/channel-math.md)。它定义分母、舍入、候选区间、CRT 和信息上限。
- **需要写代码或换题迁移**：读 [探针实现与迁移](references/probe-recipes.md)。它覆盖稳定错误值、非逐元素算子、分布探测及故障定位。
- **需要完整的已验证示范**：读 [CopySign 三轮案例](references/copysign-case-study.md)。其中参数只适用于该案例。
- **需要算数验证**：运行 [feedback_channel.py](scripts/feedback_channel.py)。先用 `python --version` 确认 Python 3.8+，再用 `--help` 查看命令；若默认解释器过旧，选择本机较新的 Python 路径。无需第三方库。工具只在本地输出，不能粘进禁止打印的提交源码。

如果另一个模型只能接收一份文件，应把本入口和当前需要的附录一起提供；仅复制入口并删除链接目标，会丢失关键操作细节。

## 必须先明确的四件事

1. **目标**：基本元信息通常为 dtype、rank、各维 shape、layout；必要时再查轴、参数、有效长度、稀疏度、数值范围、特殊值比例。只问与任务有关的内容。
2. **运行时可见信息**：host 元信息里能直接读 dtype、shape、属性吗？kernel 只能读张量吗？哪些值需要归约才能知道？能直接读的量不要通过逐元素扫描重新计算。
3. **反馈通道**：只有 Pass/WA，还是有错误数、错误率、多个输出各自反馈？百分比显示几位？比较的是元素、字节、抽样还是其他指标？测试点编号是否稳定？
4. **执行约束**：可改哪些文件？禁止哪些输出？怎样编译、提交？是否已有全通过基线？用户希望自动提交还是手动回传？是否有轮数或时间预算？

缺少阻止下一步的信息才向用户澄清。没有给出上界时，设计“超范围”标记或保留上界未定状态，不能自行把常见规模当成事实。

## 统一记号，避免最常见的混淆

| 记号 | 含义 |
|---|---|
| `N` | 本轮想探测的输入规模或某一维长度 |
| `M` | 错误率统计中实际比较的输出元素数；不一定等于 N |
| `E` | 故意造成错误且被比较器算作错误的元素数 |
| `D` | 百分比的小数位数，例如 `25.11%` 对应 D=2 |
| `S=100×10^D` | 归一化错误率的刻度总数，D=2 时 S=10000 |
| `q` | 显示的百分数去掉小数点，例如 `25.11% → 2511` |
| `c` | 希望发送的整数编码，通常 0≤c≤S |

在全量、逐元素、普通舍入模型下，`q ≈ S×E/M`。先查明 `M` 再使用公式。归约算子可能有上亿个输入却只有一个输出，只能提供一个二元结果，不能承载四位数字。

## 第一步：建立可信基线

1. 读入口、参考实现、比较器、可见样例，确认类型枚举、输出形状和误差容限。
2. 写或恢复一个尽量简单的正确版本。优先可靠性，不在这一阶段追求极致速度。
3. 已有同一版本全通过记录时直接使用，不为“走流程”额外提交。
4. 若没有可信基线，先验证基线；稀疏 WA、未初始化输出、越界和并发竞争都会污染反馈，必须先修复。
5. 在允许修改的文件中留一个明确开关，例如 `probe_enabled=false` 可恢复正确计算。保留正确路径。

不要通过“不写输出”“提前退出”“越界”“崩溃”表示一个分支。未写内存可能碰巧等于参考，运行错误也不是可靠的 WA 位。

## 第二步：建立候选与记录

为每个测试点维护记录，至少包含：

```text
测试点标识；探针版本/公式；原始 Pass/WA 和原始百分比字符串；
已确认字段；候选集合/区间/余数；依赖的比较器和舍入假设；
样本范围（若有）；下一项待解决的不确定性。
```

区分四种结论：

- **精确值**：在已经检验的通道模型下只剩一个候选。
- **区间或候选集合**：有多个可能，全部保留。
- **同余关系**：例如 `N mod 5000000=3`，绝不能记成 `N=3`。
- **统计观测或推测**：例如连续段中约 50% 为正，不等于全量比例，也不证明随机分布。

可把记录放在用户允许的工作区文件中。如果用户只允许修改一个提交文件，就在对话中记录，或把分析文件放入单独获准的目录，不能擅自改其他源文件。

## 第三步：选择信息量合适的探针

按当前可用反馈选方案，不必机械经历所有方案。

| 现有条件 | 优先方案 | 必须检查 |
|---|---|---|
| 只有 Pass/WA | 类型分组、二进制编码、阈值二分 | 错分支至少有一个确定错误；测试点稳定 |
| 有可靠错误率，M 足够大 | 一个整数编码映射为错误数 | 舍入、浮点中间精度、码间隔 |
| 类型与规模都未知 | 分离区间编码类别，区间内编码规模片段 | 类别间有间隔；小 M 另列候选 |
| 规模低位已知 | 发送高位/候选编号 | 上界或溢出标记；不能把余数当完整数 |
| M 太小，编码碰撞多 | 枚举实际可达反馈，候选排序或 Pass/WA | 本轮仍需模拟；不能盲信排名编码 |
| 元信息已够，还需统计 | 对明确谓词的位置故意出错 | 全量还是样本；分母、容差与可恢复精度 |

### 错误率编码的最小实现

host 能直接获得一个整数 `z` 时，先把它映射为 `c`，再发送：

```text
E = floor((M*c + S/2)/S)  # 最近整数，半入；S 为偶数
每个输出先算正确结果
若输出的全局下标 i < E，则写一个确定会被判错的值
否则写正确结果
```

64 位计算可用拆乘：`E=(M/S)*c+((M%S)*c+S/2)/S`。仍要检查每项范围；多维元素数的连乘也可能溢出。

当 M≥S 且百分比由足够精度的精确比例正常四舍五入得到时，可以恢复 c；实际 float32 中间计算可能错一档。通道未校准时留保护间隔或用更少档位。读取数学附录后再决定 10000 档是否适合。

### 节约提交的原则

- 每次提交同时探测全部稳定编号的测试点；允许每个点按自身 dtype、shape 或分支选择编码。
- 一轮可拆分为“类别区间 + 数值低位”，或“高位区间 + 样本统计”，但先证明两部分不串扰。
- 提交前模拟整个候选域或边界，检查碰撞和范围；提交后保留所有匹配候选。
- 已知信息不要反复发送。下一轮尽量编码候选编号或剩余高位。
- 保护间隔、验证位和超范围标记会占容量，但可以避免浪费整轮；不要只追求理论档位数量。
- CRT 是恢复多个同余条件的工具，不会凭空扩大信息量；已能直发高位时，不必为了使用 CRT 而增加轮数。

## 第四步：实现前进行确定性检查

在本地完成以下检查；不具备编译条件时明确说明是数学/源码检查。

1. **错误构造可靠**：包含零、负零、最小整数、NaN/Inf、比较容差等实际可能值。要证明比较器会算错，不能只证明位模式不同。
2. **计数准确**：多核条件用全局下标，尾部处理正确，输出只写一次，没有写竞争，`0≤E≤M`。
3. **码本可解**：逐候选运行相同的整数取整，再模拟显示；不能只代入连续百分比公式。
4. **歧义可见**：测试极小 M、刚过阈值、区间边界、范围外、大数。把碰撞留在候选表而不是删掉。
5. **便于还原**：核对探针开关、轮号、修改文件和原始反馈的对应关系。记录本轮意图与解码规则。

禁止输出的限制适用于提交源码；本地分析脚本可以输出候选和校验结果。不要把分析用的打印误带到提交文件。

## 第五步：一次一轮地闭环

提交前告诉用户三件事：修改了哪个文件、这轮能确定什么、预期 WA 是否正常。没有自动提交条件时，给出可提交文件后等待用户结果。

收到反馈后：

1. 将每行绑定到实际提交的探针版本，保存原始百分比的精度。
2. 运行本地解码，按精确模型枚举，必要时加入已经测得的舍入误差。
3. 交叉核对所有点。出现无候选、落入未使用区间或跨轮矛盾时，先排查通道与实现，不强行给唯一答案。
4. 报告本轮新确定的值与仍未知的内容，再判断是否还有值得提交的探针。
5. 只有确实影响后续决策的未知信息才继续。不要让用户重复问“还要不要提交”。

遇到编译错误或 Runtime Error，该轮没有获得所设计的数值信息。先修复并沿用同一轮号或明确标记修订版本，不把异常当成普通 WA 解码。

## 换题时的必做适配

- 矩阵 `numel` 相同可能 shape 不同；分别探测 rank、各维或候选 shape 索引。
- 归约/排序/多输出题先算实际可控的输出容量，不能套 1D 逐元素的 E 个错误方法。
- 输入值统计需要读取或归约；host 只能看到元信息不代表它能直接读设备输入。
- 分类属性、布尔参数、轴、stride、layout 可以按有限候选编码；动态范围和未知上界要留扩展分支。
- 多输出的错误率可能合并，也可能逐输出统计；没有证据不要简单相加。
- 特殊值、容差、允许多个正确答案会改变“确定错误”的定义。读 [探针实现与迁移](references/probe-recipes.md) 选择适合的构造。

## 停止条件与交付

满足用户所需元信息后，先评估继续逆向是否能改变实现或测试决策。CopySign 通常知道 dtype 和 N 就足以构造性能测试；具体随机元素往往没有额外价值。别把这个判断泛化为所有算子。

最终交付应包含：

1. 数据表：精确值、区间、余数或未知状态写清楚。
2. 若有统计：谓词定义、全量/样本、样本位置和误差范围。
3. 提交次数、已验证事实与仍依赖的假设。
4. 提交文件当前处于探针还是正确模式；怎样恢复。用户已授权恢复时直接恢复，若任务是保留探针用于复现则保持并标注。
5. 明确“无需继续提交”，或给出下一轮具体目标和文件；不要只问“是否继续”。

## 一分钟操作提示

```text
读题和比较器 → 定义目标字段 → 找到全通过基线 →
确定输出比较分母 M → 选择高容量且稳定的探针 →
本地枚举检查碰撞 → 修改允许的源码 → 提交/等反馈 →
按整数模型解码并更新候选 → 目标满足则停止。
```

如果模型拿不准数学公式，先运行工具或照案例重放验证，不能靠“百分比看起来像”直接猜长度。
