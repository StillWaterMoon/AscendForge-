# CopySign 实例：用三轮错误百分比恢复 dtype 和 N

这是一份已经走过评测反馈的实例记录，供通用流程遇到相似问题时参考。这里的五种 dtype、枚举值、百分比偏移、模数、范围上限和对齐方式，都来自这一题及其运行环境。处理其他题时，必须重新读取接口、参考实现和评测反馈，不能把这些参数当作平台通用规则。

配套的本地计算工具见 [feedback_channel.py](../scripts/feedback_channel.py)。脚本用于枚举候选、核验码本和解码；它的本地输出不属于提交到 OJ 的 `kernel.asc`。

在本技能目录 `oj-feedback-reverse-engineering` 中运行以下命令，可以重放本例：

```bash
python scripts/feedback_channel.py copysign-case
```

## 1. 目标、限制和已知信息

题目要求计算一维 CopySign：结果的绝对值来自 `x`，符号来自 `s`，输入和输出 dtype 相同，长度均为 N。允许的 dtype 为 `int8`、`int16`、`int32`、`float16`、`float32`。

用户允许修改的提交文件只有 `kernel.asc`，且该文件不能包含 `print`、`printf`、`cout` 等输出语句。每次提交可见 15 个测试点各自的 Pass/WA、输出错误百分比和运行时间。错误百分比显示到小数点后两位，例如 `45.09%`。用户在 OJ 提交，随后把完整反馈交给模型解码。

本次逆向的最低目标是恢复每个测试点的 dtype 和 N，以便构造相同类型、相同规模的数据进行验证和性能分析。在成本合适时附带获取正数分布信息。目标没有要求恢复每个元素的随机取值。

这里的“错误百分比”先作为待验证通道使用，而不是预先断言平台一定按全部 N 个元素计数。三轮反馈与整数取整模型一致，为本次使用这个模型提供了证据；这不等于已经验证了平台所有题目的比较器、特殊值处理和取整实现。

## 2. 先建立全部通过的基线

### 2.1 参考实现比题面更具体

仓库的 `reference.py` 实际执行：

```python
def impl(x, s):
    return np.copysign(x, s).astype(x.dtype)
```

题面写“s 为零时符号视为正”，但 `np.copysign` 对浮点数读取符号位，`-0.0` 会提供负号。浮点 NaN、无穷和符号位也不能简单用 `s < 0` 完整表示。因此本次基线按浮点位模式拼接结果：

```text
float32: (x_bits & 0x7fffffff) | (s_bits & 0x80000000)
float16: (x_bits & 0x7fff)     | (s_bits & 0x8000)
```

这说明实现应核对真正的参考程序，不能只凭题面自然语言推断边界语义。本次没有单独证明隐藏输入包含负零、NaN 或无穷，也没有证明评测器逐位比较这些值。基线全部通过只说明它通过了当时这 15 个用例。

整数分支先使用无符号中间值计算绝对值和取负，避免直接计算有符号最小值的相反数，再转回目标整数类型。本次工具链和参考结果通过了评测。其他语言、编译器或题目中不能直接假设越界整数转换总有相同语义，需重新核验。

### 2.2 编译问题先解决，不能混入数据推理

最初内核声明导致核类型推导失败。将声明改为以下形式后继续：

```cpp
template <typename Operation>
__global__ __vector__ void CopySignKernel(/* ... */)
```

`__vector__` 是这份 Ascend C 实现及当时编译环境需要的修正，不是所有 OJ、所有 Ascend C 内核都应机械添加的规则。编译失败没有提供隐藏 dtype 或 N 的有效信息。

### 2.3 稀疏 WA 来自基线自身的写入问题

最初实现用多核标量 GM 读写，分核边界按 32 字节对齐。当时 15 个测试点中，第 3、5、6 点分别出现 `2.73%`、`0.26%`、`0.17%` 的错误，其余通过。

随后仅将分核边界改为 64 字节对齐，全部 15 点通过。分核方法先按以下单位分配连续区间，再对末尾裁剪到 N：

```text
elements_per_unit = 64 / sizeof(T)
units = ceil(N / elements_per_unit)
将 units 尽量均匀地分配给各核
每个核仅写自己的完整单位及最后一个被裁剪的尾部
```

修正结果强烈支持“相邻核标量写入共享缓存行导致问题”的判断，但没有独立硬件实验将该机理完全证明。本例经验是：先排除自身的并发、边界和未初始化问题，再把错误比例解释为主动探针反馈；不能将“64 字节”泛化为所有后端的统一解决办法。

通过后的标量版本是正确性基线，不是高性能版本；最后一个测试点用时约 `75.2 ms`，而页面最优用时约 `568.37 μs`。本次元信息逆向不能据此声称完成了算子优化。

## 3. 定义一个可计算的反馈通道

### 3.1 明确写错，不依赖不写输出

每个元素先按基线计算正确结果 `v`。若该位置应故意写错，就把 `v` 改为另一个值并照常写回；其余位置写正确结果。所有元素都写一次，分核边界沿用已经通过的方案。

本次所用坏值为：

```text
整数：v < 0 时写 +1，否则写 -1。
浮点：v 的符号位为 1 时写 +1.0，否则写 -1.0。
```

对有限参考值，这个构造不会与正确值相等，绝对差至少为 1，也不会因为把零写成零而漏掉预定错误。它比“不写输出”“总写零”“只翻低位”稳定。仍必须核验评测器的容差：极宽的绝对容差、按整张量聚合的判定，以及某些不正确的 NaN 比较逻辑，都可能破坏“每选中一个位置就计一个错误”的假设。无穷和 NaN 的判错行为应单独验证，不能只靠有限值证明。

本次结果与预定错误数量一致；没有证据时不要把这个坏值方案宣称为任意比较器上的必错构造。

### 3.2 统一整数单位，避免把百分数乘错

以下符号贯穿本例：

| 符号 | 含义 |
|---|---|
| N | 元素总数，内核运行时可以读取 |
| E | 故意写错的元素个数 |
| p | 页面百分数，如 `45.09`，不是 `0.4509` |
| q | 百分数的百分之一单位，`q = 100 × p`，如 `4509` |
| S | 反馈整数刻度，本例 `S=10000`，不表示采样长度 |
| T | 第三轮采样窗口长度 |
| d | 本例自行定义的紧凑 dtype 编码 |

理想的计数模型为：

```text
p = round_to_2_decimals(100 × E / N)
q = round(10000 × E / N)
```

把目标 q 记为 c，选择：

```text
R(N,c) = floor((N × c + 5000) / 10000)
E = R(N,c)
```

实现中避免直接计算可能溢出的 `N*c`，等价写为：

```cpp
(n / 10000) * code + ((n % 10000) * code + 5000) / 10000
```

所有长度、计数和重建 N 的算术使用足够宽的整数。本例使用 `int64_t`；在另一个范围更大的任务中仍需重新检查溢出。

当 `N >= 10000` 时，E 的取整误差反映到 q 上至多为 `5000/N`，不超过 0.5。在按最近值显示两位小数且边界取整一致的模型下可读回目标 c。本例使用非负数向上处理半值的整数模型；换题前必须确认显示是否截断、四舍五入、抽样或经过其他聚合。边界可能受到中间浮点数表示影响，反馈不符时必须重新列候选，不能强行四舍五入到想要的码字。

当 `N < 10000` 时，E 只能取 `0..N`，可辨认的反馈等级少于百分数的 10001 个显示等级，不能把 `q=c` 当作必然成立。极小 N 时，单次反馈根本没有足够状态同时区分五种 dtype 和任意 N。

## 4. 本例的 dtype 映射

先从接口和实际实现确认原始 dtype 枚举，再建立紧凑编码。本例映射如下：

| 类型 | 接口原始枚举 | 探针编码 d |
|---|---:|---:|
| float32 | 0 | 0 |
| float16 | 1 | 1 |
| int8 | 3 | 2 |
| int16 | 4 | 3 |
| int32 | 5 | 4 |

不要把原始枚举直接当作 d，也不要把这五种类型的顺序照搬到其他题。

三轮结束后发现测试点的类型顺序是 `int8,int16,int32,float16,float32` 重复三次。这个规律是结果，不是提前使用的推理前提。

## 5. 第一轮：同时读取 dtype 和 N 的低三位

最终实际提交的第一轮公式是：

```text
c1 = 500 + 2000 × d + (N mod 1000)
E1 = R(N,c1)
故意写错位置 [0,E1)，其余位置正确计算。
```

注意偏移是 **500**，不是讨论阶段曾出现的 1000。

对足够大的 N，各类型的目标百分比区间为：

| d | 类型 | 目标百分数区间 |
|---:|---|---|
| 0 | float32 | 5.00%–14.99% |
| 1 | float16 | 25.00%–34.99% |
| 2 | int8 | 45.00%–54.99% |
| 3 | int16 | 65.00%–74.99% |
| 4 | int32 | 85.00%–94.99% |

若已确定 `N >= 10000`，先从区间求 d，再求：

```text
a = q1 - 500 - 2000 × d
a = N mod 1000
```

第一轮还不知道哪些 N 很小，所以对每个 q1 同时保留两种解释：

1. 大 N 分支：相应的 d 和低三位 a。
2. 小 N 分支：对每个允许的 d 枚举 `n=1..9999`，精确执行 E1 和显示取整，保留预测 q1 与实测一致的 `(d,n)`。

不能从百分比的两位小数直接读取小 N 的后三位。例如第 2 点 q1 为 6523，机械读取会得到 23，但真实 N 是 1024，其后三位是 24。

本次所有第一轮反馈的小 N 候选只落在一个 dtype 上，因此 dtype 都已能确定；这只是对本次反馈枚举后的事实，不是任意反馈的保证。

## 6. 第二轮：区分小 N，并读取大 N 的下一位段

第二轮按运行时 N 分支。

### 6.1 N 小于 10000：传回候选桶中的序号

设第一轮对某个固定 d、固定显示 q1 产生的全部小 N 候选，按 N 递增排列为：

```text
C(d,q1) = [n0,n1,n2,...]
```

代码在运行时重新计算自身的第一轮预测显示，并统计同 dtype、同第一轮显示且小于 N 的候选个数，得到从 0 开始的 `rank`。随后：

```text
E2 = floor((N × (rank+1) + 50) / 100)
```

即用接近 `(rank+1)%` 的错误率传出候选序号。解码时不能直接将百分数减一作为 rank；必须对桶内每个候选代入公式，再执行显示取整，与实际 q2 匹配。

本例实际四个小点的候选桶如下：

| 点 | d | 第一轮小 N 候选，按升序 | 真实 rank | p2 |
|---:|---:|---|---:|---:|
| 1 | 2 | 1009,2007,5008,8009,9009 | 0 | 0.99% |
| 2 | 3 | 1018,1021,1024,2022,2025,3023,4024,6022,6023,7023,7024,9023 | 2 | 3.03% |
| 3 | 4 | 1098,2095,2096,4097,4098,5096,5097,5098,7097,8097,9097,9098 | 3 | 4.00% |
| 4 | 1 | 26,182,208,1196,2192,3191,5193,6192,7192,8192 | 9 | 10.00% |

对这四个实际桶逐候选检验，第二轮显示在桶内均无碰撞，分别唯一得到 N 为 `1009,1024,4097,8192`。

本例全部小 N 第一轮桶的候选数检查结果不超过 48，故名义 rank 目标百分比低于 50%；但是“候选数足够少”本身不证明没有反馈碰撞，也不证明极小 N 不会因 E 的量化跨过分支范围。必须检查实际桶的每个候选。不要将本次四个桶内无碰撞推广为任意输入范围、任意码本均无碰撞。

### 6.2 N 至少为 10000：传回下一段五千进制码

大 N 分支为：

```text
b = floor(N / 1000) mod 5000
c2 = 5000 + b
E2 = R(N,c2)
```

目标百分比范围 `50.00%..99.99%`。按通道模型可读回：

```text
b = q2 - 5000
r = 1000 × b + a
r = N mod 5000000
```

此时 **r 不是完整 N**。例如第 11 点得到 r=0，并不说明 N=0；它表示 N 是 5000000 的倍数，且已经进入大 N 分支。

第一轮和第二轮组合的是低位和下一位段，属于基数编码；这里没有使用中国剩余定理。不能把 `N mod 1000` 和 `floor(N/1000) mod 5000` 错写为两个独立的同余式，也不需要为 1000 和 5000 套互素模数条件。

本次后 11 点得到：

```text
r = 65537,262144,1000003,2000000,4194304,
    3000003,0,1777216,3,3554432,4999997
```

第二轮以后小点 N 已知，大点仍存在 `N=r+5000000×h` 的不同候选。第三轮负责区分 h，不凭运行时间或常见的 2 的幂直接猜 N。

## 7. 第三轮：恢复高位，并附带采样正数统计

### 7.1 小 N：只统计全量 x>0

`N<10000` 的点已由前两轮唯一确定。第三轮正确计算每个元素，只在 `x[i]>0` 时故意改错。因此：

```text
E3 = count(x > 0)
```

这里是数值比较意义的正数：整数严格大于 0；浮点 +0 和 -0 都不算，NaN 不算，正无穷算。不要与“符号位为正”混淆。该轮探测的是 x，不是 s。

因为已知 `N<10000`，相邻整数错误数量在 q 上的间隔大于 1，所以显示可唯一恢复计数。四个小点的计数见后表。

### 7.2 大 N：用不重叠百分比区间传 h

设：

```text
h = floor(N / 5000000)
```

如果 `h>=64`，故意让全部 N 个结果错误，显示 `100.00%` 作为明确的范围外标记。不能将范围外输入对 h 取模后悄悄编码成范围内的值。

如果 `0<=h<64`，定义整数边界：

```text
L = 10000 - floor(10000/(h+1))
W = floor(10000/(h+1)) - floor(10000/(h+2))
band(h) = [L,L+W-1]，两端均包含。
```

64 个 band 首尾连续且互不重叠，合计覆盖 `q=0..9846`；最后一个 band 为 `[9844,9846]`，与范围外标记 q=10000 分开。

当 `W>=5` 时：

```text
B = R(N,L+2)
T = R(N,W-5)
位置 [0,B)：全部改错。
位置 [B,B+T)：仅当 x[i]>0 时改错。
其余位置：正确计算。
```

设采样窗口 `[B,B+T)` 内的正数个数为 P，则：

```text
E3 = B + P，0<=P<=T。
```

B 和 T 的独立整数取整误差已计入边界分析；对于本分支 `N>=10000`，实测 q3 应仍在 band(h) 内。两端留出的空隙用于防止采样比例极端或取整使反馈跨入相邻 band。

当 `W<5` 时：

```text
B = R(N,L+floor(W/2))
T = 0
只改错前 B 个位置。
```

该分支只传 h，不提供正数信息。`W=5` 时，虽然进入前一个分支，仍有 `T=0`，也不能估计正数比例。

### 7.3 第三轮解码顺序

1. 先判断是否为 q3=10000 的范围外标记；如果是，保留 `h>=64` 并重新设计上界探针，不能声称已恢复完整 N。
2. 在 64 个区间中查找唯一满足 `L<=q3<=L+W-1` 的 h。若找不到，不强行归入最近区间，应检查比较器、错误构造、反馈输入或探针版本。
3. 使用 64 位整数还原 `N = h×5000000+r`。
4. 根据还原后的 N 重算 B 和 T，而不是用近似百分数反推它们。
5. 只有 `T>0` 时才计算采样正数比例，并给出误差范围。

本次大点的 `(h,L,W)` 为：

| 点 | h | L | W |
|---:|---:|---:|---:|
| 5–9 | 0 | 0 | 5000 |
| 10 | 1 | 5000 | 1667 |
| 11 | 2 | 6667 | 833 |
| 12 | 3 | 7500 | 500 |
| 13 | 5 | 8334 | 238 |
| 14 | 6 | 8572 | 178 |
| 15 | 7 | 8750 | 139 |

这不是等宽的高位编码。h 增大时 band 变窄，留给正数比例的精度降低。

### 8.2 大点的正数比例是连续窗口统计

对按最近值取整的两位百分数，可以先保守使用：

```text
q3-0.5 <= 10000×(B+P)/N <= q3+0.5
```

由此求出整数 E 的范围，减去 B，再截到 `0..T` 得到 P 的范围。这里两端都包含，故对半值舍入规则保持保守。若算出的区间为空，说明当前模型或输入记录有问题，不能硬选一个 P。

配套工具默认使用 half-up 的精确区间，即 `q3-0.5 <= 10000×E/N < q3+0.5`，右端不包含。下表为保持保守而包含两端，因此遇到恰好落在右端的整数计数时，会比工具多包含一个候选。例如点 8 的 P 上界在精确 half-up 模型下为 499699，本表为 499700；点 11 分别为 410499 和 410500。这是精确模型与保守边界的区别，不是解码矛盾。

点估计为：

```text
positive_ratio_estimate = (N×q3/10000-B)/T
```

## 9. 这个实例为何只用了三次探针提交

每次提交对全部 15 个测试点同时编码，没有逐测试点单独提交，也没有为五种 dtype 依次提交五次。百分比通道在大 N 上一次可携带多个十进制位；小 N 的量化问题用候选枚举和候选序号解决。

第三轮没有再为正数计数增加一次全局归约。它直接把“采样窗口中选中多少位置”变成错误数量，顺带利用 h 区间内部的剩余反馈精度。代价是只得到窗口比例且精度因 h 而异，明确接受这个限制即可。

三轮不包括建立正确基线期间的编译修复和对齐修复。不能写成“从空实现到全部元信息只需三次提交”，也不能保证另一个题目同样三轮完成。

## 10. 何时结束，下一步不应机械做什么

本次元信息阶段的完成条件已经满足：

- 15 个点的 dtype 都已明确。
- 小 N 候选已唯一，大 N 的余数已补齐高位，完整 N 均可由原始反馈复算。
- 范围外标记没有出现，解码未依靠常见尺寸猜测。
- 正数统计已区分全量计数和窗口比例，量化误差有明确范围。

此时继续获取随机元素、反复细化接近 50% 的正数比例，通常不会改变 CopySign 的正确实现或优化方案。只有一个明确的后续决策依赖未知属性时，才值得再探测，例如某个简化是否要求不含负零、NaN、无穷或整数极值。先说明“该信息会改变什么决策”，再为它支付提交成本。

恢复 dtype 和 N 可用来生成相同类型、相同规模的测试张量；它不等于恢复原始输入。窗口正负比例接近一半也不足以复制数值范围或特殊值分布，更不应将推测的数据替代真实的 CopySign 计算。

结束探测时，应恢复已验证的正确性基线，关闭有意损坏结果的开关，并对最终准备提交的代码重新检查。当前实例代码使用 `kMetadataProbeEnabled` 和 `kMetadataProbeRound` 区分探针状态；这个记录本身不声称已经替用户完成恢复或再提交，必须以实际代码状态和最新反馈为准。

## 11. 可迁移的经验与不能照搬的参数

可以迁移的是：先建立正确基线，核对真实参考语义；读取接口中本来就可见的元信息；把问题转成可判别的反馈编码；明确错误构造和显示精度；小规模精确枚举；分轮保留余数和候选；设置溢出标记；在同一轮顺带获取有用的分布信息；达到目标后停止。

不能照搬的是：五种 dtype 的集合和顺序、接口枚举、64 字节分核、阈值 10000、第一轮偏移 500、步距 2000、模数 5000000、高位上限 64、递减 band 公式，以及本次坏值对未来比较器的有效性。新题先确定哪些输入特征会影响实现，再按可见反馈、规模范围和提交预算重新选择这些参数。
