# 探针实现、迁移与故障定位

本文件按“拿到一道新题后如何落地”组织。数学定义见 [channel-math.md](channel-math.md)，经过实测的完整实例见 [copysign-case-study.md](copysign-case-study.md)。

## 1. 先列所需字段，避免只会找 N

| 算子类型 | 常见必要字段 | 可能影响实现的附加字段 |
|---|---|---|
| 逐元素 | dtype、rank、shape、广播维 | 对齐、连续性、零/负零/特殊值 |
| 归约 | 输入 shape、输出 shape、axis、keepdim | 有效长度、累加精度、极值 |
| 矩阵乘 | M、N、K、转置、dtype | batch、stride、layout、稀疏结构 |
| 排序/TopK | 长度、轴、k、稳定性、升降序 | 重复值、索引类型、合法答案是否唯一 |
| 稀疏/索引 | 形状、nnz、索引类型、有效范围 | 索引重复、排序情况、分布和局部性 |
| 带标量参数 | shape、dtype、参数候选 | 参数是否随测试点变化 |

不能仅恢复 numel 就声称知道矩阵尺寸；也不能只知道输入 shape 就声称输出分母相同。

先给每个未知量标记“可从元信息直接读”“可从张量局部读”“需全局归约”“当前不可访问”。编码方案必须适合访问路径。例如 host shape 可直接映射为错误数，而正数总数需要 kernel 统计或逐元素谓词。

## 2. 怎样制造确定错误

### 2.1 通用接口

把实际计算和探针分开：

```cpp
value = ComputeCorrect(input, global_i);
if (ShouldCorrupt(global_i, metadata, input)) {
    value = MakeDefinitelyWrong(value, comparison_rules);
}
Store(output, global_i, value);
```

这里的“分开”是代码职责，不要求增加文件或 kernel。先保存输入值，避免原地写入后再读取的语义变化。

### 2.2 精确比较的常见构造

以下是候选模板，使用前仍要读比较器：

| 输出域 | 示例构造 | 理由与限制 |
|---|---|---|
| 有符号整数 | `correct < 0 ? 1 : -1` | 两个候选都在类型范围内；包含 0 和最小整数；无需有符号溢出 |
| 无符号整数 | `correct == 0 ? 1 : 0` | 不同于原值；不能照抄有符号的 -1 语义 |
| bool | `!correct` | 精确比较时一定不同 |
| 有限浮点 | `correct < 0 ? +A : -A`，A>0 | 反号且非零；若存在容差，A 必须足够大且可表示 |
| 浮点位表示 | 按正确结果符号写相反符号的有限 ±A | 可覆盖 ±0，需处理 NaN/Inf 的比较约定 |
| 索引输出 | 在合法集合中选确定不同的索引 | 若集合只有一个值或多答案都可接受，不一定可行 |

不要用以下方法代替证明：

- 全写 0：正确结果本来为 0 就不出错。
- 直接取负：0 仍可能相等，最小整数会溢出，NaN 语义不确定。
- 加 1：大浮点可能舍入回原值，整数可能溢出，容差可能接纳。
- 只翻负零符号位：按数值比较时 +0 和 -0 相等。
- 统一写 NaN：比较器可能忽略 NaN、把双方 NaN 视为相等或直接拒绝整次输出。
- 故意不写、越界或 Runtime Error：没有稳定的元素错误数。

### 2.3 近似比较

例如比较器为 `abs(actual-reference) <= atol + rtol*abs(reference)`。必须保证选出的坏值越过这个阈值。对有限参考值，反号 ±A 且 A>atol、rtol<1 往往有充分裕量，但先验证类型最大值和比较器细节；不把它视为适用于任意容差的定理。

若没有任意参考值都可用的坏值，应利用已证实的输出范围选择候选，或承认这条通道不适合精确计数，换为经过校准的更粗探针。特殊值会被跳过时，E 不能只数“尝试破坏”的位置。

## 3. 只有 Pass/WA 时怎么做

### 3.1 类型分组

为 K 个类型分配互不相同的二进制编号。第 j 轮：若运行时类型编号的第 j 位为 1，则制造至少一个确定错误；否则正常计算。约 `ceil(log2 K)` 轮即可区分类型。

例：5 个类型编号 0..4，需要 3 位，不必分别为每个类型提交一轮。实际库的 dtype 枚举可能是 0、1、3、4、5；先映射到紧凑编号 0..4，不要误当连续。

### 3.2 长度二分

已知 `L≤N≤U`：用阈值 t，在 `N>t` 时故意错，其他正确。WA 说明 N>t，Pass 说明 N≤t。每点可以根据已有状态使用不同阈值；host 必须能按可观察的元信息区分对应分支。

未给上界时先做倍增范围探测，或按机器类型有限位直接探位。空输出 M=0 时无法制造输出元素错误，要单独处理，不能由 Pass 推断 N 的任何位。

### 3.3 稳定编号要求

每次结果按相同输入的测试点对齐才能跨轮组合。发现编号重排时，先寻找可信标识；仅凭耗时相近不能可靠匹配。输入元素每轮随机重生成时，dtype/shape 可能仍稳定，正数个数和单个元素则不能跨轮拼接。

### 3.4 完整示例：ReduceSum 的 dtype 与长度联合编码

设输入为 `[N]`，已知 `1≤N≤2^20`，dtype 仅有 float16、float32、int32，输出为一个同类型标量。因此 `M=1`，每点每轮只有 Pass/WA 两个状态，显示 100% WA 也没有增加容量；按 `N%10000` 设置“错误比例”不能传回四位数字。

先确认允许修改的文件能通过已有类型特化和 tiling/参数取得 dtype、N，并已有全通过基线及第 2 节所述的确定错误构造。若仅允许改 `kernel.asc`，就在其最终归约标量写回处加入探针；不要改输出 shape、另改 host 文件或猜测不可见的元信息。

将类型映射为紧凑编号 `d`：float16→0、float32→1、int32→2。联合索引为：

```text
z = d * 1048576 + (N - 1)       # 1048576 = 2^20
0 <= z <= 3145727              # 共 3*2^20 个候选，22 位足够

第 j 轮，j = 0,1,...,21：
    value = 正确的最终归约标量
    若 ((z >> j) & 1) == 1：value = 确定会被比较器判错的值
    由原来的最终写回者显式写出 value
```

`z` 可用 32 位无符号整数，移位范围为 0..21。下一轮从 `j=0` 开始：`2^20*d` 不影响最低位，因此 **N 为偶数时故意错，N 为奇数时保持正确**。每次提交让全部稳定编号的测试点按自身 dtype、N 执行同一公式；22 轮同时恢复全部点，不是为每点分别提交 22 次。

记录每点每轮的原始反馈、版本和 j。正常 WA 记为 `b_j=1`，Pass 记为 `b_j=0`；编译失败、RE、超时或未运行不能当作位。齐备后解码：

```text
z = sum(b_j * 2^j for j in 0..21)
d = z // 1048576
N = z % 1048576 + 1
```

只接受 `d∈{0,1,2}`；恢复出 `d=3` 即无效候选，应排查轮号、点号、元信息、基线和坏值构造，不能擅自改成最近的合法值。中途也可保留所有与已收到位一致的候选；只剩一个时该点即可停止探测。

**轮数下界有前提**：若单点全部 `3*2^20` 个候选都仍可能，且没有可用的跨点关系或其他反馈通道，每点每轮至多取得一个可靠二元结果，则任意方案最坏至少需要 `ceil(log2(3*2^20))=22` 轮。上述方案达到这个最坏下界；校准、排错或额外验证提交另计。已有反馈或公开先验可缩小候选：可只查询未知位，或在运行时能够识别候选并计算其编号时，将剩余 K 个候选重新编号为 `0..K-1`，用 `ceil(log2 K)` 位发送；已唯一确定的点无需继续。

若 N 的上界未知，不能照发 22 位后宣称完整恢复；先探明范围或加入可解码的超范围分支，再选择位宽。仅发送有限低位仍只能得到余数。若已确认更小范围或更少类型，也应重新计算候选数，不固定沿用 22 轮。

## 4. 有错误率时的代码模板

### 4.1 基数片段

要发送整数 z，单轮容量为 R 个稳健码字时，第 j 轮发送 `floor(z/R^j)%R`，把该值映射到有码间隔的 c。读回各片段后按基数重建。

这是基数编码。`N%1000` 和 `(N/1000)%5000` 的拼接也属于位段编码，并非 CRT。对无上界整数，有限轮只能知道余数；要另发高位或溢出标志。

### 4.2 Host 与 kernel

```cpp
// host；所有值均为非负，M>0，0<=code<=scale。
int64_t ProbeCount(int64_t M, int64_t code, int64_t scale) {
    return (M / scale) * code
         + ((M % scale) * code + scale / 2) / scale;
}

// kernel；每个 core 的 begin/end 已确定且互不重叠。
for (int64_t i = begin; i < end; ++i) {
    auto v = CorrectAt(i);
    if (i < errorCount) v = DefinitelyWrong(v);
    output[i] = v;
}
```

探针只用元信息时，code 和 errorCount 由 host 计算即可，不需要读回设备数据。数据值谓词由 kernel 判断，需归约的全局计数则需要不同方案。

### 4.3 小分母专门处理

N 或 M 很小时只能出现 `M+1` 种错误数。即使界面显示四位数字，也不能强行编码上万种状态。

做法是：枚举每个候选的实际 E，再算实际显示 q；保留匹配的所有候选。下一轮发送候选的编号，或使用 Pass/WA 二分。候选编号也要再经过实际 E 和 q 模拟，不保证天然无碰撞。

如果同一元信息候选组的候选太多，拆轮或降低每轮承担的字段数。不要为了省一轮把有碰撞的码字当成精确结果。

## 5. 获取数据分布与具体元素

### 5.1 全量谓词统计，不需要归约内核

逐元素一一对应且 M=N 时：

```text
若 predicate(x[i], s[i]) 为真，就把该位置写错；否则正确。
```

于是 E 就是谓词满足数量。可探测正数、零、负零、NaN、Inf、范围内元素、整数最小值、两个输入符号是否一致等。先定义谓词，例如“x>0”不包括零和 NaN；“符号位为 0”会包括 +0 和部分 NaN，二者不是同一统计。

若需要同时获取多个统计，可把输出分为若干不交叠窗口，但单个合并错误率只给一个和。除非用互不相交的编码权重并验证可解，否则不能从一个和分离多个任意计数。

### 5.2 元信息与样本统计共用一轮

选择一个能表示元信息类别的错误率区间，设固定全错前缀 B，再设样本长度 T：

```text
[0,B)：全部写错
[B,B+T)：仅当 predicate 为真时写错
其他位置：正确
```

观测 E=B+P，P 是这段样本中的满足个数。用错误率反推 E 的整数区间，再减去 B，并与 `[0,T]` 求交。

必须确保 `B+T≤M`，且所有 `0≤P≤T` 都留在同一元信息区间；两端留舍入裕量。区间窄时统计精度会变差。连续样本只能描述该段，不能默认它是独立随机抽样。

可以用确定性分散下标采样减少只看前缀的偏差，但要保证映射无重复、样本数精确；除非给出抽样假设，不输出全量比例的统计置信区间。

### 5.3 需要准确大计数时

已知 M 且 D=2，原始谓词计数通常有约 M/10000 宽的候选区间。换一个固定全错前缀并不会自动产生无限精度。

若用户确实需要精确全量计数，可先做设备归约得到 P，再把 P 当作元信息整数编码，多轮发送其基数片段或 CRT 余数。这需要额外 kernel、workspace、同步和时间；先确认环境接口与用户目标，不为一个没有用途的统计强行增加复杂度。

### 5.4 具体元素

要读取某个位置的值，可以在设备上读取该元素的整数值/浮点位表示，再用**独立的输出槽位**发送编码。不能认为破坏该位置的一个输出就能传回完整值。还必须证明每轮输入相同，重复运行和多核读取没有竞争。

若有 L 个元素、每个 b 位、每点每轮最多 C 位反馈，完整恢复至少约 Lb/C 轮。浮点按位编码可保留 NaN payload，但是否有用途取决于用户目标。不要把“能做”当成“值得做”。

已知 RNG 名称/种子也不必然能重现：还需版本、位生成器、采样区间、dtype、调用顺序、每次重置方式。公开 sample.py 仅描述样例；不能自动认定隐藏测试共享种子或元素。

## 6. 非逐元素题怎样迁移

### 6.1 归约

输入 N=65536、输出一个标量时 M=1，只能用正确/错误传一个 bit。可以按 N 的位选择标量是否错，或者阈值二分；不允许改变输出 shape 来增加通道容量。

若输出为多个分组归约结果，可用实际输出个数 M 编码；输入 N 与 M 是两个不同变量。

### 6.2 排序、TopK、多答案

先查比较器是否按位置比较值、是否看索引、是否验证合法集合。交换两个相等值不算错，交换不同值也可能被不看顺序的校验接受。要针对实际校验定义确定错误。

### 6.3 矩阵与稀疏结构

shape、stride、转置、nnz 等元信息可映射到码字；用足够输出元素承载。多个字段组合时先计算笛卡尔积候选量，设计混合基数或分轮发送。对于大维度，分别传低位和高位，并保留范围外标记。

## 7. 现象到排查动作

| 现象 | 先查什么 | 不要得出什么结论 |
|---|---|---|
| 基线只有少量错 | 语义、溢出、尾部、数据竞争、缓存共享 | 不直接归因于隐藏特殊数据 |
| 目标错误率和反馈略差一档 | 整数取整、float32 比例计算、显示舍入 | 不立刻调整 N 去凑常见数 |
| 目标全错却少一部分错 | 坏值与参考相同、容差、NaN 排除、抽样 | 不把差额直接当零元素个数 |
| 结果不稳定 | 未初始化、并发覆盖、编号/输入变化 | 不跨轮强行 CRT |
| 没有任何候选 | 版本错配、分母、舍入、实际公式、类型枚举 | 不选择“最近”的候选当精确值 |
| Runtime Error/超时 | 内存边界、接口、归约同步、额外开销 | 不按普通 WA 解码 |
| 正数约一半 | 只报告观察范围和精度 | 不证明均匀/正态/固定 RNG |

Ascend 的 `__vector__` 标注、64 字节缓存行避共享等是平台排查项；从案例学到的是“先消除实现噪声”，不是所有平台都必须同样分块。

## 8. 本地工具用法

在技能目录运行；`python` 替换为可用的 Python 3.8+：

```bash
python scripts/feedback_channel.py --help
python scripts/feedback_channel.py plan --length 65537 --code 1037
python scripts/feedback_channel.py display --length 1009 --errors 500
python scripts/feedback_channel.py interval --length 1009 --percent 49.55
python scripts/feedback_channel.py interval --length 10000000 --percent 50.00 --code-slack 1
python scripts/feedback_channel.py enumerate --max-size 9999 --base 500 --dtype-step 2000 --modulus 1000 --dtype-codes 2 --percent 45.09
python scripts/feedback_channel.py crt --residues 2,3,2 --moduli 3,5,7
python scripts/feedback_channel.py copysign-case
python scripts/verify_channel.py
```

预期要点：`display` 得 49.55%；`interval` 唯一得到 500；示例 `enumerate` 得 1009、2007、5008、8009、9009；CRT 得 `z=23 mod105`，不是无上界的唯一 23。案例重放得到本次 15 点完整规模和统计区间。

通用命令支持 `--digits` 和 `--rounding half-up|floor`。`--code-slack 1` 表示允许反馈多/少一个显示刻度，是有界误差假设，不是“修复任何未知比较器”的开关。若仍无候选，排查假设。

`enumerate` 的公式固定为 `c=base+dtype_step*dtype_code+size%modulus` 且假设 M=size；它不是任意探针语言。其他公式需要调用脚本函数或另写本地枚举，不能用这个命令强套。

`copysign-case` 是专用示范，默认读取 [原始反馈](copysign-observations.json)，不适用于其他题。它没有把本次最终 N 写成解码输入，而是从三轮百分比重新推得结果。
