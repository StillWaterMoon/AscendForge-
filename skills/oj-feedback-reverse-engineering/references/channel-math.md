# 评测反馈通道：数学模型与可恢复信息

本参考用于设计、解码 Pass/WA 和错误占比探针。所有“精确”结论都带有评测器模型前提；未验证前只能记为假设。先区分数据规模、被比较的输出数量和页面显示精度，再选择公式。

## 1. 符号与分母：输入 size 不一定是错误率分母

| 符号 | 含义 |
| --- | --- |
| `N`、`size`、`numel` | 某个输入的元素数量；具体指哪个输入必须写清 |
| `shape` | 完整维度，例如 `[B, H, W]`；一般不能由 `numel` 唯一恢复 |
| `M` | 评测器计算错误率时实际比较的单位数，即分母 |
| `E` | 其中被评测器判定为错误的单位数，`0 <= E <= M` |
| `D` | 页面百分数保留的小数位数，例如 `12.34%` 对应 `D=2` |
| `S = 100 * 10^D` | 将错误比例映射到显示整数的缩放倍数；`D=2` 时 `S=10000` |
| `p` | 页面显示的百分数，例如 `12.34` |
| `q = p * 10^D` | 页面代码整数，例如 `12.34%` 对应 `q=1234` |

本题一维逐元素 CopySign 若比较完整输出，则 `M=N`。通用题目可能有归约、拼接、多个输出、掩码或抽样，不能沿用这个等式。例如输入 `[B,H,W]` 归约成 `[B]` 时，输入元素数是 `B*H*W`，错误率分母可能只有 `B`。

还要确认“错误单位”是元素、字节、行、张量还是样本。若一个测试点内含多个用例，页面可能按全部元素汇总，也可能先算各用例比例再平均；后者通常不能用一个整数分母 `M` 建模。

`M=0` 时没有可供故意改错的输出元素，下面的比例公式不适用。不得通过越界写入制造反馈。

## 2. 理想模型：完整比较后按 half-up 四舍五入

假设评测器比较全部 `M` 个输出，实际错误数为 `E`，且页面直接把真实百分比按通常的“四舍五入，恰好一半时向上”显示，则：

\[
q = Q(E,M) = \left\lfloor \frac{S E}{M}+\frac12 \right\rfloor.
\]

这里的 `1/S` 是比例的一格，`100/S` 是百分数的一格。`D=2` 时，一格为 `0.01` 个百分点，半格为 `0.005` 个百分点。不要把 `0.01%` 误写成比例 `0.01`。

### 2.1 从显示值反推错误计数

half-up 模型满足：

\[
q-\frac12 \le \frac{SE}{M} < q+\frac12.
\]

因此，整数错误数的精确候选区间为：

\[
E_{\min}=\max\left(0,\left\lceil\frac{(2q-1)M}{2S}\right\rceil\right),
\]

\[
E_{\max}=\min\left(M,\left\lceil\frac{(2q+1)M}{2S}\right\rceil-1\right).
\]

上界的 `-1` 来自严格小于，不能省略。若下界大于上界，说明该观测不符合当前分母、错误计数或舍入模型。

例如 `D=2, M=1000000, p=49.87%`，则 `q=4987`，得到：

\[
498650 \le E \le 498749.
\]

若探针让所有正数对应的输出都错误，这只能说明正数数量在该区间内，不能直接宣称恰有 `498700` 个正数。相反，`M=1024, p=25.00%` 时，区间只含 `E=256`，这才是该模型下的精确计数。

解码端优先使用任意精度整数或有溢出检查的整数运算。不要用二进制浮点计算这些区间的端点，也不要直接套用默认的 `round`：某些语言采用 ties-to-even，即“恰好一半取偶数”，与此处模型不同。

### 2.2 保守区间与额外显示误差

若只是不确定半格端点如何处理，可以先用更宽的包络：

\[
\max\left(0,\left\lfloor\frac{(q-1/2)M}{S}\right\rfloor\right)
\le E \le
\min\left(M,\left\lceil\frac{(q+1/2)M}{S}\right\rceil\right).
\]

这个区间刻意保留端点附近的额外候选，不应称为精确解。

若已证明观测整数 `q_obs` 与理想整数 `q_ideal` 相差最多 `h` 格，其中 `h` 为非负整数，则对 `q_ideal in [q_obs-h, q_obs+h]` 的所有合法档位取区间并集。half-up 模型下可以直接写为：

\[
E_{\min}=\max\left(0,\left\lceil\frac{(2(q_{obs}-h)-1)M}{2S}\right\rceil\right),
\]

\[
E_{\max}=\min\left(M,\left\lceil\frac{(2(q_{obs}+h)+1)M}{2S}\right\rceil-1\right).
\]

`h` 必须有依据。观察过几次不变不等于证明误差最多一格；评测器抽样、提前结束或改变分母时，也不能用随意扩大一格来修复模型。

### 2.3 数值不相等不一定计为错误

浮点比较器可能以 `abs(actual-reference) > atol + rtol*abs(reference)` 一类规则判错，或者使用相对误差、ULP 距离、整体范数等标准。只有逐单位判错时，`E` 才能解释为错误单位的数量。一个很小的数值扰动可能仍算正确；制造 NaN、无穷大或非法整数转换也可能触发特殊规则、崩溃或非确定行为。

因此，编码器控制的是“被比较器判错的数量”，而不是“被代码写成不同位模式的数量”。先用确定的有限值、边界值和特殊值验证错误构造，确认选中的位置确实全部判错、未选中的位置保持正确。若 Pass 允许一定数量的错点，或错误占比只统计首批失败、抽样失败、某种聚合误差，上述 Pass/WA 含义与比例公式都需要另建模型，不能继续宣称全量精确计数。

## 3. 将任意整数编码成错误比例

“只让正数错误”直接测量的是正数占比。更高效的方式是先在程序内部得到目标整数 `T`，例如输入元素数、某一维长度、正数总数，再把 `T` 的一段数字编码为人为控制的错误数。

### 3.1 理想的满密度编码

选取代码 `c in [0,S]`，期望页面显示 `q=c`。让程序正确计算全部输出，然后恰好改错：

\[
E=\operatorname{round}_{half\text{-}up}\left(\frac{Mc}{S}\right)
=\left\lfloor\frac{Mc+S/2}{S}\right\rfloor
\]

个被比较的输出单位。因为 `S=100*10^D` 总是偶数，`S/2` 是整数。

不要直接在固定宽整数里计算 `M*c`。下面给出 `D=2` 的无该乘积溢出写法：

```cpp
// 前提：0 <= c <= 10000，M 能用 uint64_t 表示。
// 这是算术示例；实际内核需使用编译器支持的对应整数类型和限定符。
uint64_t encoded_error_count(uint64_t M, uint64_t c) {
    constexpr uint64_t S = 10000;
    const uint64_t whole = M / S;
    const uint64_t rem = M % S;
    return whole * c + (rem * c + S / 2) / S;
}
```

这里 `whole*c <= M`，`rem*c+S/2 < S*S`，最终结果不超过 `M`，所以对 `S=10000` 的 `uint64_t` 实现没有这些中间溢出。更改显示精度后，要重新检查 `S*S` 等上界；不能把这段证明直接套到任意大的 `S`。

误差界为：

\[
\left|\frac{SE}{M}-c\right|\le\frac{S}{2M}.
\]

当 `M>S` 时，右侧严格小于 `1/2`，页面必然还原 `q=c`；当 `M=S` 时，`E=c`，仍然精确。因此，**在精确 half-up 模型下，`M>=S` 足以保证所有代码可恢复**。

例如 `D=2` 时令基数 `B=S=10000`，每次编码：

\[
c_j=\left\lfloor\frac{T}{B^j}\right\rfloor\bmod B.
\]

页面的 `q` 就是一个四位十进制数字组，`12.34%` 表示代码 `1234`。两次可恢复已知 `0 <= T < 10^8` 范围内的整数。计算数字组时可重复做整数除法，避免盲目计算可能溢出的 `B^j`。

若 `c=0`，理论错误数为零，页面可能只显示 Pass；在正确性基线稳定、Pass 确实表示零错误时，可以把它解为代码零。不能把编译失败、超时、崩溃或测试未运行解成代码。

### 3.2 浮点中间运算会破坏临界保证

上面的保证依赖真实比例最终只舍入一次。若评测器先使用 float32 计算、存储或格式化百分比，临近半格的值可能跨档。

例如 `M=10001, c=5000`，编码得到 `E=5001`。真实百分比是：

\[
100E/M\approx50.00499950005\%,
\]

half-up 应显示 `50.00%`。但若先把这个百分比压成 float32，可能得到约 `50.0050011`，再显示成 `50.01%`。不同的 float32 运算顺序也可能产生不同结果，不能仅凭这一例推断评测器的具体实现。

应先用有间隔的代码校准，例如 `D=2` 时用 100 或 1000 个代码，而不是立刻用满 10000 档。若 `B` 整除 `S`，可编码数字 `d in [0,B-1]`，令目标代码 `c=d*S/B`，按最近的合法代码解码。更大的代码间距能容纳一定的显示误差，但仍需验证误差界，不能保证抵抗抽样或错误分母。

### 3.3 截断模型需要换公式

若页面采用向下截断，则：

\[
q=\left\lfloor\frac{SE}{M}\right\rfloor,
\quad
E\in\left[\left\lceil\frac{qM}{S}\right\rceil,
\left\lceil\frac{(q+1)M}{S}\right\rceil-1\right]\cap[0,M].
\]

四舍五入编码的 `E` 可能落在目标代码下方，显示为 `c-1`。在确认是精确截断模型且 `M>=S` 后，可以改用 `E=ceil(M*c/S)`，使页面还原 `c`。其整数实现也应先按 `M/S` 与 `M%S` 分解乘积。不要把一个模型的编码器与另一个模型的解码器混用。

### 3.4 信息上限与小输出

只看百分比字段，一次反馈至多有 `S+1` 个显示档位，信息上限为 `log2(S+1)` 比特。`D=2` 时约为 `13.29` 比特；10000 进制的一组数字就是对这个容量的接近利用。若额外利用 Pass/WA 区分“零错误”与“有错误但显示 0.00%”，应将这个状态单独建模。

当 `M<S` 时，实际错误数只有 `0,1,...,M`，百分比最多产生 `M+1` 种状态，无法承载任意 10000 档代码。例如 `M=7` 时只有 `0%、14.29%、28.57%` 等八种理想结果，不能稳定制造 `10.00%`。

小输出应降低基数、使用 Pass/WA，或枚举候选：对每个候选目标与候选分母，按实际编码公式算出 `E`，再按显示模型算出预期 `q`，只保留吻合候选。不要在 `M<S` 时直接把页面整数当作原始代码。枚举结果若有多个，保留整个集合，并设计下一次能把它们分开的探针。

## 4. Pass/WA：稳定的一个条件位

在已验证的正确性基线上，让条件 `P` 成立时显式写入确定错误的结果，否则写正确结果。若错误必然会被检查且 Pass 定义明确，则 WA 表示 `P=true`，Pass 表示 `P=false`。这是二元条件查询；具体分支方向可以相反，但记录必须一致。

“不写输出”不能作为确定错误，未初始化内存可能复用上次结果。写零、取负或翻转符号位也不普遍保证错误：正确答案可能为零，整数最小值取负有边界问题，浮点比较可能把正负零视为相同。错误构造必须针对输出语义和比较器验证。

常见数学用途：

- **阈值二分**：查询 `N > t`。已知整数范围 `[L,U]` 时，约 `ceil(log2(U-L+1))` 次可定位 `N`。同理可查询可访问的维度、步长、计数或极值是否越过阈值。
- **类别分组**：给 `k` 个 dtype 或布局类别分配唯一二进制编号，第 `j` 次按编号的第 `j` 位选择故意错误。理想情况下 `ceil(log2(k))` 次即可分开全部类别；五种 dtype 可用三次。必须有可信的全通过基线，才能把“全 Pass”视为其中一个合法编号。
- **位查询**：查询整数目标的第 `j` 位是否为一。可非自适应执行，但需要确定整数宽度、符号解释和安全移位范围。恢复大计数前，程序仍需先算出该计数。

阈值二分适合维护连续区间，位查询适合固定宽整数，类别分组适合有限候选集。它们都不依赖百分比精度，但仍依赖探针不会因为其他错误产生 WA。

## 5. 中国剩余定理：合并已测得的余数

CRT 并不会凭空产生数据；它将已经可靠获得的多个余数合成为一个整数候选类。设两两互素的模数为 `m_1,...,m_k`，探针已经得到 `T mod m_i = r_i`。令：

\[
P=\prod_i m_i,\quad P_i=P/m_i,
\quad a_i=P_i^{-1}\pmod {m_i}.
\]

则：

\[
T\equiv\sum_i r_iP_i a_i\pmod P.
\]

例如余数为 `T mod 7=4`、`T mod 11=2`、`T mod 13=6`，则 `P=1001`，解为 `T=123 mod 1001`。`123` 与 `1124` 都符合这些余数；只有已知 `0<=T<1001`，才能唯一确定 `T=123`。更一般地，已知闭区间 `[L,U]` 且 `U-L<P` 时，至多有一个匹配整数；仍需检查该整数是否确实位于区间内。

余数本身可通过位查询、对余数做阈值查询，或百分比编码取得。若只提交“`T mod m == r` 时 WA”，一次只回答是否等于指定余数，不能直接读出 `0..m-1` 的任意值。线性枚举所有余数通常比二分或编码昂贵。

| 方法 | 每次反馈表达什么 | 主要条件与取舍 |
| --- | --- | --- |
| Pass/WA 阈值或位查询 | 一个条件位 | 简单稳定，提交次数随目标比特数增长 |
| 小基数比例编码 | 一个有间隔的数字组 | 容量低于满密度编码，能留出显示误差裕量 |
| 满密度基数编码 | 接近 `log2(S)` 比特 | 需要足够大的 `M`，并确认计数、舍入与数值精度 |
| CRT | 一个余数，多个余数合并 | 需要可靠余数与唯一性范围；不自动提高反馈容量 |

同等反馈精度下，CRT 没有超过信息上限的特殊能力。它适合模运算方便、已有余数或需要额外模数交叉校验的场景。一个错误余数也能合成看似精确的错误整数，所以可用未参与恢复的模数验证结论。未互素的模数须使用广义 CRT，并检查一致性；唯一解周期是最小公倍数，不是直接相乘。

## 6. 固定错误数量，反推未知分母

若能保证恰好 `K>0` 个被比较的输出错误，且已知 `M>=K`，则 half-up 模型有：

\[
q-\frac12\le\frac{SK}{M}<q+\frac12.
\]

当 `0<q<S` 时：

\[
\frac{2SK}{2q+1}<M\le\frac{2SK}{2q-1}.
\]

整数候选区间因此是：

\[
\max\left(K,\left\lfloor\frac{2SK}{2q+1}\right\rfloor+1\right)
\le M \le
\left\lfloor\frac{2SK}{2q-1}\right\rfloor.
\]

用页面百分数 `p` 表示的等价式是：

\[
\frac{100K}{p+\frac12 10^{-D}}<M
\le\frac{100K}{p-\frac12 10^{-D}}.
\]

例如 `D=2,K=256,p=25.00%` 时唯一候选是 `M=1024`。`K=100000,p=10.00%` 时却只能得到 `999501<=M<=1000500`。显示的小数精度决定区间宽度，不能把中心估计当作精确值。

边界单独处理：

- `q=0`：对于确实存在的 `K>0` 个错误，只有 `M>2SK`，即 `M>=2SK+1` 的下界；`0.00%` 不代表零错误。若同时显示 Pass 且 Pass 确定表示零错误，则当前“恰有 K 个错误”的假设不成立。
- `q=S`：仍可能有少量正确输出。已知 `M>=K` 时，`K<=M<=floor(2SK/(2S-1))`；`100.00%` 不必意味着恰好所有元素错误。
- `K=0`：比例恒为零，无法反推 `M`。

若代码只是“改错前 K 个合法位置”，实际错误数是 `min(K,M)`。当 `M<K` 时不能继续代入 `E=K`。看到 `100.00%` 还要考虑整个输出不足 K 个的分支。多个探针要对所有候选 `M` 模拟实际错误构造，再取候选集合交集。

## 7. 分布计数：直接测占比与先归约再编码

必须先定义统计谓词：`x>0`、`x<0`、`x==0`、符号位为负、输出为正、非有限值等可能给出不同计数。浮点负零、NaN、掩码、被排除位置和题目对零的特殊规定都影响谓词。不要把“负号位数量”写成“负数数量”而不解释。

有两条不同的信息路径：

1. **直接谓词改错**：仅在谓词成立的位置改错。完整逐元素比较下 `E` 就是谓词计数，百分比直接给该计数的区间。实现常较轻，但大 `M` 时两位百分比只能给粗粒度数量。
2. **先统计，再编码计数**：先准确归约出谓词数量 `C`，再把 `C` 的位、基数数字或余数编码成独立的 Pass/WA 或错误比例。反馈容量依旧有限，但多次可以恢复完整整数，而不是只测同一个比例。

重复提交完全相同的直接谓词探针，在确定性评测器下只会得到相同区间，不会因次数增多自动恢复更多小数位。新的谓词、已知偏移、子区间或互补探针有时能缩小候选集合，但必须逐次建立真实计数关系；不要承诺“多测几次就能精确”。

若评测器只抽样 `m` 个输出，直接探针观测的是样本里的计数 `C_sample/m`，不自动等于全量 `C/M`。只有随机抽样机制与抽样量已知时，才能谈统计估计和置信区间；固定但未知的抽样可能存在系统偏差。全量归约后再编码也可能被输出抽样破坏，尤其当固定改错一个连续前缀时。

精确归约存在执行成本：需要读全部数据、局部计数和可能的跨核合并。跨核同步、全局工作区、额外 kernel 或 host 侧启动步骤未必能在题目允许修改的单个文件里正确实现。应核实可用接口、同步语义、资源和超时限制；遵守用户授权的文件与提交范围，不能因数学上可行就擅自增加外部访问、修改其他文件或提交探针。

## 8. 恢复结论的边界

- `numel` 相同的张量可以有不同 shape、stride、布局与广播关系。矩阵、批量、稀疏和变长题目应分别恢复影响行为的元数据，不能只记录一个总元素数。
- dtype、shape、范围和计数只确定数据特征，不唯一确定每个位置的元素。即使正负数量精确，符号的排列和数值大小通常仍有大量可能。
- 不能凭“随机生成”“可能固定种子”直接重建元素。要复现，需要可靠确认生成器算法、种子、调用顺序、分布、转换方式以及可能相关的软件与设备版本；同一种子在不同实现中不保证同一张量。
- 每条结论应附带当前使用的分母、显示模型、探针谓词和候选范围。新反馈矛盾时回退到这些模型检查，不要继续把不一致观测拼成一个精确答案。
