# 恢复算子输入规格与构造本地测试

目标是建立有证据的工作负载规格，为后续编译、正确性测试和性能优化提供依据。恢复对象是 rank、shape、dtype、axis、布局、元素数和算子属性；不默认恢复原始 tensor 数值、随机种子或官方数据分布。

本阶段只保存小型 JSON、Markdown、源码和诊断日志，不生成或保存大规模 tensor，也不运行数据生成器。

在用户授权范围及平台允许的诊断方式内开展工作。先使用公开契约、下载模板、已有日志和用户提供的结果。诊断被平台明确拒绝时保留原因，不改换编码方式规避拒绝。此技能不授权读取评测机其他用户数据、修改校验器或绕过访问控制。

## 1. 工具与工作区

复用实际可用工具，不凭文档假造接口。在用户的三工具平台中：

- read_problem(url)：读取题面。
- submit_official(...)：按已注册 schema 冻结工作区源码并排队提交。
- read_official_evaluation(submission_id)：读取状态及原始评测结果。

模板、源码、笔记和解码脚本使用本地文件能力处理。自有服务器测试只有在实际配置并提供接口时才调用。工具文档描述哪些字段存在不等于官方实际返回了这些字段。

诊断实现也通过 `submit_official` 提交；**不要因为没有已有 submission_id 就停止**。先建立正确基线，再提交一个受控探针，新的 submission_id 由工具返回。宿主会把诊断提交放到独立任务中，不写入优化任务的尝试/提交，也不更新优化 best。

开始前保存正确基线和源码哈希。诊断候选独立存放；宿主只能从固定位置提交时，提交前切换准确文件、核对哈希，快照冻结后恢复工作区。诊断失败不降低生产 best，诊断耗时和分数不得混入性能排名。

## 2. 建立契约与证据表

读取题面、模板 ABI、调用入口、参考实现与比较器。确认哪些元信息在正常调用中可见，哪些需要推断。区分输入元素数和输出元素数，特别是归约算子；不能把输出长度直接解释成输入长度。

为每个 case 保存稳定 testcase_id、题目版本和观测时间。只有页面序号时标记对应关系未验证；跨提交排序或测试集变化时不能直接拼接观察。

每项属性使用四种证据状态：

- measured：可关联原始反馈和准确制品的直接观测。
- provided：来自用户资料，尚未独立复核。
- inferred：由约束推导，保留前提和剩余候选。
- unknown：目前不足以确定。

记录字段：case_id、属性、值或候选集合、来源、submission_id、source_hash、原始反馈、解码假设和验证状态。一次猜测不得在后续上下文中升级为事实。

## 3. 先判断反馈能提供什么

查看真实响应：是否有 stdout/stderr、编译诊断、逐点 verdict、误差比例、计数或仅有耗时。优先使用平台允许且直接可读的元信息输出；不需要编码时不要增加探测。

把编译信息与运行时信息分开：语言标准、编译器宏、头文件版本和编译目标不能独自证明物理 SoC、可用核心或缓存容量。编译日志的版本也不能代表全部运行库版本。

若分析已有编码诊断，或平台允许开展相应诊断，先明确通道语义：

1. 反馈是错误元素比例、通过比例、最大误差，还是某种聚合分数？不能只凭字段名判断。
2. 分母是输出元素数、输入元素数，还是其他数量？
3. 显示有几位小数？是舍入还是截断？原始 API 是否比页面精确？
4. 是否逐点反馈？重复观测是否稳定？
5. 比较器如何处理 NaN、Inf、容差和未写入输出？不得预设这些行为。

优先在自有小型评测器中用已知输入校准编码与解码关系。若远端比较器未知，本地校准只能证明本地通道，不证明远端相同。通道解释不明确时停止精确解码，记录可确定的范围。

## 4. 选择恢复方式

根据可见反馈、未知量范围和实际规则选择方法；不机械套用 CRT。一次诊断可以服务多个 case 或互不干扰的属性，但必须避免通道含义混淆。

### 4.1 直接证据和约束

先从公开模板、允许的日志、已有运行记录提取元信息，再使用代数关系缩小候选。

总元素数 N = 各维长度乘积。仅有 N 不能恢复 rank 和 shape；[6]、[2,3]、[3,2] 有相同 N。dtype、rank、各维长度和 axis 必须分别获得证据，不能靠常见尺寸补齐。

对于沿某轴的 Scan：outer 为轴之前各维乘积，length 为该轴长度，inner 为轴之后各维乘积；N=outer*length*inner，scan_count=outer*inner。这些等式是交叉检查，不一定唯一确定原始 shape。

负 axis 与归一化 axis 分开记录；从归一化结果不能反推出原始 axis 的符号。

### 4.2 基数编码（radix）

当诊断通道能可靠区分 B 个符号时，可分析整数的 B 进制分位编码：第 j 位 d_j=floor(N/B^j) mod B，恢复 N=sum(d_j*B^j)。radix32 表示 B=32，不等同于 CRT。

离线示例：N=1009 的低两位是 17、31，因此 N=17+31*32。只有已知 N<1024 或已确认高位为零时才能唯一确定 N；否则还可能有更高位。

通道可区分多少符号由实际反馈精度决定，不是越大越好。若一个符号对应多个候选，应传播候选集合，不强行取最近整数。

### 4.3 错误比例通道（radix128 分位编码）

这是已在同类 CANNJudge 题目中实测过的通道，优先级高于机械套用 CRT。适用前提是平台逐测试点返回**输出错误元素比例**，且分母和比较器语义可校准。

#### 先建立正确基线

1. 先用正常实现跑出 `0.00%` 错误、`Pass` 的基线；基线本身有错时不能把错误比例当信息通道。
2. 再提交“只故意破坏固定数量输出、其余保持正确”的最小探针，校准：
   - 分母是输出元素数 N、输入元素数，还是多个输出之和；
   - 页面四舍五入还是截断，显示几位小数；
   - NaN/Inf、哨兵值、未写入输出如何判定；
   - 重复提交是否稳定。
3. 分别用 `bad=1、2、10` 观察比例是否满足 `p≈bad/N`。不满足或有非零基线时停止该路线。

#### 编码方式

探针仍然正常计算算子，然后在输出写回后覆盖**前 m 个输出元素**为不合法的哨兵值；其余输出保持正确。若每个被覆盖元素都判错：

```text
p ≈ m / N
```

对一个输出元素数 N，取 7 位一段：

```text
d = (N >> S) & 127
v = 2 * (d + 128 * t) + 1          // 1..511 的奇数
m = floor((N * v + 256) / 512)
```

其中 `t` 是 dtype 位：已验证案例中 `t=0` 为 FP32、`t=1` 为 FP16；具体映射必须从题面/模板确认，不能只凭惯例。

`m` 也可用代码中的商余形式避免大整数：

```text
q = 512
m = (N / q) * v + ((N % q) * v + q / 2) / q
```

覆盖后页面比例约为：

```text
p ≈ 100 * v / 512
```

相邻 `v`（相差 2）的比例间隔约 **0.390625 个百分点**，通常大于两位小数的显示粒度，但仍必须保留取整候选，不能直接把显示值当精确 v。

#### 分位与上界

已验证案例使用：

```text
S = 0, 7, 14, 21
```

得到 `d0..d3` 后：

```text
N = d0 + 128*d1 + 128^2*d2 + 128^3*d3 + 2^28*k
```

四个 7 位段只恢复低 28 位。必须再做独立范围验证，例如：

```text
若 N < 2^28：正常计算，全部 Pass
若 N >= 2^28：覆盖全部输出，全部判错
```

实测案例中该验证得到 10/10 Pass，才支持 `N < 2^28`。没有范围验证时只能报告 `N mod 2^28`，不能宣布精确 N。

#### 重要限制

- 该通道恢复的是**某个输出 tensor 的元素数**，不是 rank 或各维 shape；`N=6` 仍可能是 `[6]`、`[2,3]`、`[3,2]`。rank/shape 必须另有证据。
- 多输入、多输出时先确认错误比例的分母；必要时对每个输出单独探测。
- `N < 512` 时 `m` 可能直接等于 N（全错），不能按常规比例解码；记录该边界并改用其他观察。
- 哨兵值必须保证判决为错误，不能假设 `-1024` 对所有 dtype/算子都非法；先在基线上验证。
- 页面比例受取整、容差和比较器特殊值影响。将显示比例转换成 v 的候选区间，若多个 v 都符合，增加一个独立观察区分，不强行取最近值。
- 这不是 CRT。它可以和 CRT 组合，但不要把 radix128 的结果称为“余数”。

#### 一次探针的执行顺序

```text
1. read_problem(url)，确认题面、输出接口、只读文件限制
2. 用正常实现取得真实基线（理想情况 0.00% / Pass）
3. 确认比较器的错误占比含义和分母
4. 只改动可编辑源码，保持正常计算
5. 在一个输出 tensor 写出后覆盖前 m 个元素
6. submit_official 提交，保存返回的 submission_id
7. read_official_evaluation 读取原始反馈和逐测试点比例
8. 记录 p、候选 v 区间、源码 hash 和假设
9. 只对能区分候选的下一段继续探测
10. 用未参与拟合的范围/联合检查验证，再写 specifications.json
```

探针失败时先检查 baseline 是否仍正确、哨兵是否真的判错、分母是否选错、页面比例是否被取整；不要用“再换个哨兵”掩盖通道未校准。用户暂停后不再提交。

### 4.4 中国剩余定理（CRT）

当已有反馈能可靠取得 r_j=N mod m_j 时，可用 CRT 合并余数。两两互质模数的乘积 M 决定唯一恢复范围：只能先确定 N mod M；有已知范围 0<=N<U 且 M>=U 时，才能唯一恢复 N。

离线示例：N mod 5=3、N mod 7=1、N mod 11=0，得到 N mod 385=253。没有上界时不能直接宣布 N=253。

选择模数时综合可分辨符号数、取值上界和执行成本。非互质模数使用广义 CRT，先验证余数对最大公约数相容，有效周期是最小公倍数而非直接乘积。不相容应定位反馈、case 对齐或解码错误，不能修改观察强行凑解。

CRT 是余数合并方法，不会自动提供远端余数。没有有效反馈通道时，不声称仅靠 CRT 可以恢复数据。将最后一个独立模数或其他独立约束留作验证，而非全部用于拟合。

### 4.5 区间与条件观察

若只有布尔或粗粒度反馈，先判断能否对候选施加可靠约束。只有已经证明观察关系单调，才适用二分；不将任意 WA 当成“大于”或“小于”。单次异常可能是实现错误、同步错误或基础设施故障，不能直接解读成属性值。

纯耗时通常只能形成规模类别或性能特征假设。缓存、调度、编译路径和负载都会影响时间，不能单凭耗时反推出唯一 shape 或芯片型号。

## 5. 正确处理量化与歧义

若已确认页面按最近值显示两位小数的百分比 p，则真实百分比通常落在 p±0.005 个百分点的范围内；还需处理端点、tie 规则和 0/100 边界。转成比例时再除以 100。截断显示应使用不同区间。

若比例已确认是 k/n，结合取整规则求所有满足显示区间的整数候选，不直接把显示比例视作精确值。n 未知时，这不是一个已知精度的直接数值通道。小输出、容差、比较器特殊值处理会使不同编码映射到相同显示值。

保留候选集合并选择下一项能有效区分候选的观察。多个余数或位数字都有歧义时，逐步合并约束，避免无界穷举。无信息增益或结果不稳定时停止该路线，不重复消耗提交。

## 6. 独立验证恢复结果

恢复候选后，使用未参与恢复的独立信息验证完整 tuple：dtype、rank、shape、axis 和必要属性。平台允许的联合诊断需证明它确实区分匹配与不匹配，避免“所有输入都会 Pass”的空验证。

校验 N、字节数、shape 乘积、输入输出关系和算子约束。记录一次联合验证覆盖哪些字段、哪些仍未验证。某个源码 10/10 Pass 不自动证明里面每条诊断分支被执行，也不证明猜出的全部规格正确。

重复观测失败时，先排查 case ID 变化、反馈截断、版本变化、诊断源码不一致和执行路径未生效，不能挑选有利结果。

外部资料中被称为已确认的表，若缺少原始证据仍标 provided。禁止把引用同一张表的两份文档当作两次独立验证。

## 7. 本阶段交付：规格，不是数据

本阶段只写 `specifications.json` 和 `evidence.md`，不生成 tensor 文件、不下载完整输出、不运行数据生成器，也不在本地分配 N 大小的缓冲区。

输出按 case 保存：

```text
testcase_id
inputs: name/dtype/shape/numel
outputs: name/dtype/shape/numel
attributes / derived
evidence_status: measured|provided|inferred|unknown
evidence_refs: submission_id / attempt_id / snapshot_id
```

未知值用 `null`；有多个候选时保存候选集合或范围，不强行填一个值。`numel` 必须和 shape 乘积一致；rank、shape、dtype 分别保留证据状态。

不要因为恢复出元素数 N 就补出常见 shape。也不要在本阶段构造“邻近/压力/泛化”数据；这些是下一阶段的工作。可以在规格中记录计划使用的 seed、边界和 checker，但不得执行生成。

## 8. 环境与性能对齐

区分三个目标：编译兼容、正确性验证、性能趋势。编译器、CANN 完整版本、目标架构、ABI 和实际编译参数决定编译兼容；设备与输入共同影响性能。

至少记录 SoC、可用核心数、可查询的片上资源、SDK/编译器、驱动、测试形状、计时边界、预热/重复策略。查询失败或返回语义不明的零值时记录未知。

相同 shape 在不同设备上也可能对应不同最佳 tile、block、缓冲和算法。限制核心数不能模拟缓存、带宽与指令差异。相同设备也不保证相同频率、负载与缓存状态。

性能比较在同一固定本地环境内做成对实验，正确性先过关。分开记录端到端耗时、kernel 时间与 profiler 数据，不把编译时间计入 kernel。缓存热/冷、输入复用、同步和重复次数保持可解释。最终收益仍需官方正常评测验证。

## 9. 提交、停止与交付

遵守提交频率、在途控制和真实外部限额，不设置固定十次或十轮限制。提交已接受但结果未知时查询原 ID，不盲目重发。收到明确平台拒绝时记录并结束被拒绝的方法。用户暂停后不再发起新提交。

恢复规格和优化实现是不同阶段：不自动把诊断扩为持续刷分。达到本地测试所需精度、剩余未知不影响下一步时可结束恢复；不为了凑满表格无限探测。

最终交付：`specifications.json`、`evidence.md`、诊断提交列表和验证结论。报告确认值、候选范围、未知项、实际执行过的检查及下一步；本阶段不交付 tensor 文件或数据生成器。生产 kernel 根据真实输入计算，不以 case 编号或预存答案替代计算。
